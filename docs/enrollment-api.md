# Managed enrollment API

The relay can run an optional management service for one-time device
enrollment and live credential revocation. The service listens on loopback;
a TLS reverse proxy exposes only the public enrollment and health endpoints.
Administrative endpoints remain reachable only through SSH or another
operator-controlled network.

## Security model

- Activation codes are random, expire, work once, and are stored only as
  SHA-256 hashes.
- Every enrollment creates a unique client ID, 256-bit device key, and tunnel
  address. Client IDs and keys are never shared between users or devices.
- Device keys are encrypted at rest using AES-256-GCM under
  `LINKFORGE_CONTROL_MASTER_KEY`.
- Administrative calls require
  `Authorization: Bearer $LINKFORGE_ADMIN_TOKEN`.
- Strict JSON limits, enrollment rate limiting, no-store responses, TLS-only
  remote clients, and redirect refusal reduce common provisioning mistakes.
- The public reverse proxy must expose only `/v1/enroll` and `/v1/healthz`.
  Never expose `/v1/admin/*` directly to the internet.

The embedded bbolt database is deliberately single-process and is a good fit
for one self-hosted or managed relay. A multi-relay/high-availability service
should put the same store interface behind a replicated control-plane
database.

## Operator workflow

Create the two deployment secrets once. The master key must decode to exactly
32 bytes; both values should be generated by a cryptographic random source and
kept out of shell history, logs, source control, and client bundles.

```text
LINKFORGE_ADMIN_TOKEN=<at-least-32-random-characters>
LINKFORGE_CONTROL_MASTER_KEY=<base64-encoded-32-byte-key>
```

Create a short-lived activation code over the loopback-only admin API:

```bash
curl --fail-with-body \
  -H "Authorization: Bearer $LINKFORGE_ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"user_id":"USER_ID","device_name":"laptop","expires_in":"15m"}' \
  http://127.0.0.1:8443/v1/admin/activations
```

Only the returned `activation_code` is given to the user. It cannot be used
again after successful enrollment.

The client exchanges it for a locally stored profile:

```bash
LINKFORGE_ACTIVATION_CODE=lf_... linkforge enroll \
  -url https://ENROLLMENT_HOST \
  -code-env LINKFORGE_ACTIVATION_CODE \
  -output profile.json
```

List devices, rotate one key, or revoke one device:

```bash
curl --fail-with-body \
  -H "Authorization: Bearer $LINKFORGE_ADMIN_TOKEN" \
  http://127.0.0.1:8443/v1/admin/devices

curl --fail-with-body -X POST \
  -H "Authorization: Bearer $LINKFORGE_ADMIN_TOKEN" \
  http://127.0.0.1:8443/v1/admin/devices/CLIENT_ID/rotate-key

curl --fail-with-body -X DELETE \
  -H "Authorization: Bearer $LINKFORGE_ADMIN_TOKEN" \
  http://127.0.0.1:8443/v1/admin/devices/CLIENT_ID
```

Rotation and revocation take effect in the running relay immediately. A
rotated profile is returned only once and must replace the device's old
profile.

## Endpoint summary

| Method | Path | Access | Purpose |
|---|---|---|---|
| `GET` | `/` | Public | Service status and client-dashboard location. |
| `GET` | `/v1/healthz` | Public | Enrollment service liveness. |
| `POST` | `/v1/enroll` | Activation code | Register one device and return its profile. |
| `POST` | `/v1/admin/activations` | Admin bearer token | Issue a one-time activation code. |
| `GET` | `/v1/admin/devices` | Admin bearer token | List non-secret device records. |
| `POST` | `/v1/admin/devices/{id}/rotate-key` | Admin bearer token | Replace one device key. |
| `DELETE` | `/v1/admin/devices/{id}` | Admin bearer token | Revoke one device. |
