# Configuration reference

Configuration is strict JSON: unknown fields fail startup so misspellings do
not silently disable a safety setting. Duration values use Go syntax such as
`"500ms"`, `"2s"`, or `"2m"`.

## Client

| Field | Meaning |
|---|---|
| `server` | Relay UDP host and port. |
| `client_id` | 32 hex characters or a UUID generated by `keygen`. |
| `psk_env` | Preferred environment variable containing the 32-byte base64/hex key. |
| `psk` | Inline key used by mode-0600 managed profiles; never commit it. |
| `tunnel_name` | Requested TUN/Wintun adapter name. |
| `tunnel_address` | Fixed IPv4 CIDR matching the relay credential. |
| `mtu` | TUN MTU; 1280 is conservative across tethered networks. |
| `paths` | Explicit physical paths. |
| `auto_discover_paths` | Add active physical, non-virtual IPv4 interfaces that own a default route. |
| `routes` | CIDRs installed through the TUN when automatic setup is enabled. |
| `traffic_mode` | `manual` uses `routes`; `all` automatically routes all IPv4 traffic. |
| `configure_interface` | Assign TUN address and routes using `ip` or `netsh`. |
| `health_interval` | Encrypted path ping interval; default 2s. |
| `handshake_timeout` | Initial per-path handshake deadline; default 8s. |
| `reorder_delay` | Maximum wait for a missing global sequence; default 80ms. |
| `reorder_window` | Maximum buffered out-of-order packets; default 512. |
| `stats_interval` | Structured aggregate/path log interval; default 15s. |
| `metrics.listen` | Dashboard/API/Prometheus bind address; empty disables it. |

Each path has:

| Field | Meaning |
|---|---|
| `name` | Stable log, dashboard, and metric label (maximum 63 bytes). |
| `local_address` | Local IPv4 source address used for the UDP socket. |
| `interface` | Interface used to discover an address when local_address is empty. |
| `weight` | Relative packet share, normally proportional to Mbps. |
| `enabled` | Optional boolean; omitted means enabled. |

The one-click `app` discovers paths and calibrates relative weights whenever
the physical path set changes. Explicit paths are the advanced/manual option
for operators who need fixed source bindings or controlled split routing.

## Server

| Field | Meaning |
|---|---|
| `listen` | Relay UDP bind address, normally `:4430`. |
| `tunnel_name`, `tunnel_address`, `mtu` | Relay TUN settings. |
| `clients` | Allow-list of names, IDs, keys, and fixed tunnel addresses. |
| `configure_interface` | Assign and bring up the TUN automatically. |
| `session_timeout` | Remove an inactive client session; default 2m. |
| `reorder_delay`, `reorder_window` | Uplink reorder bounds. |
| `stats_interval` | Structured relay summary interval. |
| `metrics.listen` | Dashboard/API bind address. Keep private or authenticate at a proxy. |

The server tunnel CIDR must contain every client tunnel IP. Client IDs and IPs
must be unique. Rotate a client without affecting others by replacing only its
key and restarting the relay.

## Route modes

The low-level examples ship with `routes: []`, which establishes the tunnel
without redirecting application traffic. The managed profile uses
`traffic_mode: "all"`.

- Split tunnel: add only private/application prefixes, such as
  `["10.20.0.0/16"]`.
- Full tunnel: set `traffic_mode` to `all`. Before the two `/1` routes are
  installed, LinkForge creates a source/interface-specific physical route
  guard for every discovered path. Stop/shutdown removes both the TUN routes
  and policy tables.

Manual route policies can still be supplied through `routes`. See
[operations.md](operations.md).
